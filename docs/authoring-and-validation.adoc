= Authoring and publication validation

This file is for authors and facilitators. Deployment configuration and publication checks do not belong in the learner walkthrough.

== Scope and source

The workshop is approximately 90 minutes for intermediate SRE, platform, and network engineers.
It starts with working application access and covers six modules followed by a conclusion.
Only this Showroom repository is changed.

The 2026-11-17 revision was checked against the local `ai-driven-network-remediation` checkout, including uncommitted AAP, Lightspeed, and tenant automation changes.
These changes are not yet an immutable published source reference.
Pin and recheck the exact quickstart revision used by RHDP before publication.

The `showroom:create-lab` and `showroom:verify-content` skills guide authoring and review.

== Required integration configuration

[cols="1,3",options="header"]
|===
|Integration |Workshop requirement
|AAP |Real controller for Network and RAN, with working inventories, credentials, execution environments, and scoped job templates
|Lightspeed |Real Ansible Lightspeed endpoint enabled for Network playbook generation; generated playbooks validated, stored in Gitea, synced, and executed through AAP
|Network targets |AAP jobs modify and verify the example edge nginx deployment; the CPU demo also requires the client, `microservice-a`, and `microservice-b` workloads in the edge project
|RAN targets |Real AAP jobs update and verify the controlled `adnr-ran-state` ConfigMap; no physical radio equipment is connected
|ServiceNow |Network-only mock retained for escalation
|Models |External MaaS through Llama Stack, plus both CPU Mantis predictors
|Documents |Network runbooks and RAN documentation ingested and ready for retrieval
|Authentication |OpenShift authentication on both dashboards; AAP console access supplied in service details
|===

The tenant bootstrap defaults to mocks with Lightspeed and the CPU demo disabled. Enable the CPU demo in the real AAP profile and supply tested image references before publishing Module 3; see `tenant/REAL-AAP.md` in the quickstart.
The workshop requires `aap.enabled=true` and `lightspeed.enabled=true`, their endpoint and credential inputs, and a successful automation bootstrap.
`tenant/bootstrap/templates/_helpers.tpl` then disables the AAP mock, enables Gitea, and sets the real AAP and Lightspeed endpoints.
The real-AAP configuration disables the independent edge fast-path healer in `tenant/bootstrap/templates/applications.yaml` so it does not compete with the AAP exercises.
These are requirements for environment owners, not learner setup steps.

The RAN templates use environment-prefixed names.
The current playbooks update `adnr-ran-state` in the edge namespace and verify the incident and selected action.
Learner instructions use the recorded job ID and the template's recognizable suffix to find the execution.

== Runtime access contract

Map the actual Showroom user data to the following attributes or update the pages when the adapter contract is finalized:

[cols="1,2",options="header"]
|===
|Attribute |Purpose
|app_namespace |Application namespace
|edge_namespace |Edge workload and RAN simulator namespace
|openshift_console_url |Optional OpenShift console link
|network_dashboard_url |Optional authenticated Network route link; otherwise locate `hub-frontend` in Routes
|ran_dashboard_url |Optional authenticated RAN route link; otherwise locate `hub-ran-frontend` in Routes
|aap_console_url |Optional AAP console link; service details must also supply access and credentials
|===

Keep credentials in private service details and Kubernetes Secrets.
The learner has read-only OpenShift access; Module 4 uses the incident card and available agent logs to review escalation evidence. The dashboard does not expose mock ticket details.
AAP access must allow inspection of the relevant templates, jobs, parameters, and output.

`ui-config.yml` enables split view with an OpenShift Console tab and Terminal tab.
Use fully resolved access URLs when adding application or AAP tabs.
Do not assume arbitrary AsciiDoc attributes expand in `ui-config.yml`.
Validate OAuth in embedded and separate tabs.

* [ ] Check the rendered architecture diagram, page layout, navigation, and access links in the deployed Showroom theme.
