= Authoring and publication validation

== Scope and assumptions

This is a draft learner workshop, approximately 90 minutes, for intermediate SRE, platform, and network engineers.
The learner starts with a provisioned tenant.
Only this Showroom repository is changed.

The source quickstart was inspected read-only at `94546a9a92667ea5d62e42857f9047bdb22caed4`, together with local uncommitted changes present during authoring, including tenant packaging.
That commit alone does not reproduce the packaging reviewed.
Before publication, replace this reference with the published immutable revision used by RHDP, and recheck behavior against it.

The invoked `showroom:create-lab` skill supplied the generation/review workflow and local AsciiDoc rules.
Its referenced common-rules and specialized file-generator/module-reviewer definitions were not available in this checkout; available references and independent generation/review agents were used.

== Deployment profile contract

[cols="1,3",options="header"]
|===
|Setting |Agreed profile
|Topology |One OpenShift cluster; no ACM hub/spoke setup
|Workflows |Network and Telco O-RAN enabled
|Namespaces |Tenant application namespace and separate tenant edge namespace
|AAP |One shared mock for Network and RAN
|ServiceNow |Network-only mock
|Lightspeed |Disabled; no mock
|LLM |Real external MaaS inference through Llama Stack
|RAN models |Real anomaly and RCA Mantis predictors on CPU in the application namespace
|Authentication |OpenShift authentication on both dashboards
|Documents |Bundled Network and RAN documents ingested automatically
|Optional integrations |Slack, LokiStack, Langfuse, Kafka UI disabled
|Other demos |CPU misconfiguration excluded
|Dedicated GPU |Not required
|===

Shared dependencies include Kafka, Llama Stack, PostgreSQL/pgvector, object storage, and ingestion.
The independent edge watcher/runner can modify nginx; successful mock AAP jobs must never be presented as proof of that change.
RAN does not use the Network ServiceNow path.

== Proposed runtime contract

These are proposed Showroom attribute names, not a claim that the RHDP adapter already emits them.
Map the adapter's actual user data to these keys or update the pages when that contract is finalized.

[cols="1,2,2",options="header"]
|===
|Attribute |Purpose |Draft behavior
|app_namespace |Assigned tenant application namespace |Visible `TENANT_APPLICATION_NAMESPACE` placeholder
|edge_namespace |Assigned tenant edge namespace |Visible `TENANT_EDGE_NAMESPACE` placeholder
|openshift_console_url |Assigned console URL |Optional rendered link; console tab uses shared ingress domain
|network_dashboard_url |Authenticated Network route URL |Optional rendered link; otherwise locate `hub-frontend` in Routes
|ran_dashboard_url |Authenticated RAN route URL |Optional rendered link; otherwise locate `hub-ran-frontend` in Routes
|gitops_url |GitOps UI URL, if learner access exists |Optional rendered link; facilitator confirms health otherwise
|===

The current learner binding uses ClusterRole `view` in both namespaces and does not grant `pods/exec`.
Pod-terminal ticket reads and internal vector-store indexing checks require an authorized facilitator.
Do not broaden learner privileges to make the draft exercises work.

Credentials come from private service details.
Do not commit tenant credentials or MaaS keys.
The proposed keys must be supplied as tenant-specific runtime attributes by the Showroom provisioning integration.

`ui-config.yml` enables split view with an OpenShift Console tab and Terminal tab.
Provisioning must provide the terminal and console embedding support.
Add or override Network, RAN, and GitOps tabs using fully resolved tenant URLs in the provisioning configuration.
Do not assume that arbitrary AsciiDoc attributes are expanded inside `ui-config.yml`, or that ${DOMAIN} identifies the tenant.
Validate OAuth in embedded and separate tabs; fall back to separate tabs if framing is blocked.

Network timeline cards summarize completed audits; they do not expose a live per-node trace.
Detailed logs depend on deployed log level.
Network chat does not receive the complete per-incident investigation.

RAN chat may fall back to the latest anomaly for an unknown ID.
These limitations are included in the learner exercises.
