= AI-Driven Network Remediation
:navtitle: Start here

Investigate a network incident, follow an AI-assisted remediation decision, and compare that workflow with radio access network (RAN) anomaly detection and root-cause analysis.
Use two dashboards on a single OpenShift cluster to connect evidence, model output, automation, and human escalation.

[IMPORTANT]
====
This workshop is a draft for the agreed tenant deployment profile.
Tenant GitOps packaging, runtime access wiring, installation, reset, and cleanup require validation in a freshly provisioned environment before publication.
Begin with a facilitator-provisioned seat; this draft does not provide a validated installation procedure.
====

== Two stories, one environment

* *Network:* Follow CrashLoop and out-of-memory (OOM) incidents through investigation and runbook retrieval to a guarded automation decision. Inspect intentional escalation to a mock ServiceNow ticket.
* *RAN:* Send sample key performance indicators (KPIs) through two real CPU predictors, then inspect retrieved documentation, a Models-as-a-Service (MaaS) explanation, and a mock automation result.

== How to read the evidence

[cols="1,3",options="header"]
|===
|Evidence label |Meaning
|*Real*
|Kubernetes observations, Kafka messaging, document retrieval, external MaaS inference, and both local RAN predictors run against live services.
|*Simulated*
|Demo alerts and KPI inputs are controlled samples. Ansible Automation Platform (AAP) executions and Network ServiceNow tickets use mocks.
|*Separate real behavior*
|The edge fast-path watcher and runner can change the example edge workload independently of mock AAP execution.
|===

A successful mock job demonstrates an integration and its recorded result.
It does not prove that a workload, network device, or radio was repaired.
