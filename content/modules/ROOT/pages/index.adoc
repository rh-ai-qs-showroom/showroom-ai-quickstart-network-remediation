= AI-Driven Network Remediation
:navtitle: Introduction

You are an engineer in a network operations team.
An alert alone does not tell you whether automation is appropriate: you need observations, relevant operating procedures, a defensible decision, and a record of what happened.

This quickstart brings investigation, AI-assisted diagnosis, and automation together so operators can follow an incident from its first signal to a recorded outcome.
This walkthrough introduces the components and guides you through the Network and radio access network (RAN) dashboards.

== What you will learn

* Follow an incident from investigation and runbook retrieval to an automation decision.
* Use Ansible Automation Platform (AAP) and Red Hat Ansible Lightspeed to run existing playbooks or generate a new response.
* Follow RAN anomaly detection, root-cause classification, and an AI-generated explanation.
* Inspect automation results and incidents that need human investigation.

== Before you begin

This walkthrough is intended for site reliability engineers, platform engineers, and network engineers with basic Kubernetes knowledge.
You should recognize pods, deployments, namespaces, and logs.
Model training, GPUs, and cluster administration are not required.

Allow about *{lab-duration}*.
The application access links and credentials are in your service details.

Continue to xref:01-overview.adoc[workflow and architecture] for a tour of the system before opening the applications.
